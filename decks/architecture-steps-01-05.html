The system,
one step at a time

You start with a jar and a laptop full of things you installed by hand. You finish with three containers, one database, and a pipeline that ships two images to a registry behind a human who has to say yes.

a running container / pipeline job a database a boundary published host port / a passed gate a gate you must pass broken / absent

These are C4 container diagrams. In C4 a "container" means a separately runnable thing — an app, a database, a web server. It lines up almost exactly with a Docker container here, which is convenient but a coincidence.

Put it in a box

branch step-01 · ~65 min
What's new: fx-app-spring/Dockerfile (multi-stage) and .dockerignore. The app runs with no JDK, no Gradle and no MySQL involved.
Watch for: the container starts and /health is green while /api/rates is a 500. "Up" and "working" are different claims — the pool is lazy. We deliberately do not fix the database here.
2

The whole stack in one file

branch step-02 · ~60 min
What's new: docker-compose.yml and .env.example at the workspace root. The database is part of the system now, not part of your laptop.
Watch for: down keeps the volume, down -v destroys it — and the seed only re-runs against an empty data directory. That one fact explains most "I changed the seed and nothing happened" bugs.
3

A second app, and the port fight

branch step-03 · ~45 min
What's new: fx-monitor/ as a sibling folder and a third service on host port 3000. Your API's build context did not grow by a byte.
Watch for: Bind for 0.0.0.0:8080 failed: port is already allocated. Container ports are private; published host ports are shared. It is always the left-hand number.
4

The machine runs the tests

branch step-04 · ~45 min
What's new: .github/workflows/ci.yml at the repo root, running ./gradlew build on every push and pull request against your existing test suite.
Watch for: the value isn't the green — it's the red you make on purpose. Break a test, watch the PR go red, then turn on branch protection so a red build can't be merged.
5

From green build to blessed deploy

branch step-05 · ~45 min
What's new: ci.yml narrowed to pull_request plus a build-only images matrix; a new cd.yml on push: [main] chains build → publish → deploy, publishing two images — fx-app-spring and fx-monitor.
Watch for: deploy sits behind environment: staging with a required reviewer — the run visibly pauses in Waiting until a human approves. GHCR owners must be lowercase or the push 400s.
